# 第 10 篇：数据入口与私有数据集制作指南

> 本文回答一个问题：**我想用自己的数据跑本方法库，三种任务（预测 / 异常检测 / 分类）分别要把数据做成什么样子、放到哪里、怎么跑？**
>
> 本库所有数据都通过 `method_lib/data_provider/data_factory.py` 的 `data_provider(args, flag)` 统一加载。加载什么文件、按什么格式解析，完全由 `--data` 参数和文件摆放位置决定。大多数情况下，**你不需要改任何代码**，只要按下面的规则放好文件即可。

---

## 1. 总体流程（三分钟速览）

```
准备数据文件
   │
   ▼
按任务放进 method_lib/../dataset/<你的数据集名>/
   │
   ▼
运行 python run.py --task_name <任务> --data <类型> --root_path ... --data_path ...
   │
   ▼
（可选）用一个小脚本验证数据能被正确加载
```

三个任务的“数据入口”总结：

| 任务 | `--data` 取值 | 你主要准备什么 | 代码自动做什么 |
|---|---|---|---|
| 长序列预测 | `ETTh1/ETTh2/ETTm1/ETTm2` 或 `custom` 或 `Solar` | 一个 CSV / txt 文件 | 自动按 70/20/10 切分训练、验证、测试 |
| 异常检测 | `MSL/SMAP/SMD/PSM/SWAT` | 训练集、测试集、标签文件（csv 或 npy） | 自动标准化、滑窗、阈值判定 |
| 分类 | `UEA` | `<数据集名>_TRAIN.ts` 与 `<数据集名>_TEST.ts` 两个文件 | 自动解析 .ts、padding、类别编码 |

## 2. 长序列预测（Long-term Forecasting）

### 2.1 数据集类型

| `--data` | 使用的加载类 | 说明 |
|---|---|---|
| `ETTh1` / `ETTh2` | `Dataset_ETT_hour` | 小时级 ETT 格式（7 变量） |
| `ETTm1` / `ETTm2` | `Dataset_ETT_minute` | 15 分钟级 ETT 格式（7 变量） |
| `custom` | `Dataset_Custom` | **最常用**：任意变量的 CSV |
| `Solar` | `Dataset_Solar` | 纯数值 txt（每行 137 个逗号分隔数） |

自己做私有数据集，**优先用 `custom`**，通用性最强。

### 2.2 CSV 格式要求（custom / ETT）

用任何表格软件或 Python 导出成 CSV，必须满足：

1. **第一列是时间列**，列名任意（通常叫 `date`），内容能被 `pandas.to_datetime` 解析，例如：
   - `2016-07-01 00:00:00`
   - `2016/7/1 0:00`
   - `2024-01-01`（日频）
2. **其余每列是一个变量**，全部是数值，不要有字符串列；
3. **建议最后一列命名为 `OT`**（Output Target）。代码里默认 `--target OT`，加载时会执行 `cols.remove('OT')`；如果没有 `OT` 列，要么把某一列改名为 `OT`，要么运行命令里用 `--target <你最后一列的名字>`；
4. 每行一个时间戳，**没有缺失值**（有缺失请先插值或删除整行）；
5. 文件放在 `dataset/<你的数据集名>/` 下，例如 `dataset/my_data/weather_my.csv`。

示例 `dataset/my_data/temperature.csv`：

```csv
date,station_A,station_B,station_C,OT
2024-01-01 00:00:00,10.2,11.0,9.8,10.5
2024-01-01 01:00:00,10.4,11.1,9.9,10.7
2024-01-01 02:00:00,10.1,11.2,9.7,10.6
...
```

### 2.3 自动切分规则（重要）

代码**不会**使用你划分好的文件，而是对整份 CSV 按行数自动切分：

$$
\text{train}=\text{前 }70\%,\qquad \text{val}=\text{中间 }20\%,\qquad \text{test}=\text{最后 }10\%
$$

所以：

- 请把数据按时间顺序排好，一整份 CSV 即可；
- 如果只想在固定区间测试，把 CSV 预先截到那个区间即可；
- 测试集在最后 10%，验证集在中间 20%，训练集在最前 70%。

### 2.4 运行命令

```bash
cd method_lib
python run.py --task_name long_term_forecast --is_training 1 --model Bi_FI \
  --model_id MyData_96 --data custom \
  --root_path ../dataset/my_data/ --data_path temperature.csv \
  --features M --freq h \
  --seq_len 96 --label_len 48 --pred_len 96 \
  --enc_in 4 --dec_in 4 --c_out 4 \
  --d_model 512 --e_layers 2 --d_ff 512 \
  --batch_size 32 --learning_rate 0.0001 --train_epochs 10 --des MyExp
```

需要改的地方：

| 参数 | 含义 | 怎么填 |
|---|---|---|
| `--root_path` | 数据集目录 | `../dataset/<你的数据集名>/` |
| `--data_path` | 文件名 | 你的 CSV 文件名 |
| `--enc_in / --dec_in / --c_out` | 变量数 | 等于“变量列数”（不含 date）。上例是 3 个站点 + OT = 4 |
| `--freq` | 时间频率 | `h` 小时、`t` 分钟、`d` 天、`s` 秒 |
| `--seq_len` | 输入长度 | 例如 96 |
| `--pred_len` | 预测长度 | 例如 96/192/336/720 |
| `--model` | 模型 | 9 个方法任选 |

### 2.5 Solar 特殊格式

如果你有“纯数值、无表头、无时间列”的数据（例如光伏出力矩阵），用：

- 文件：每行 $M$ 个逗号分隔浮点数，共 $T$ 行；
- 运行：`--data Solar --data_path solar_AL.txt --enc_in <M>`；
- 注意：Solar 加载器内部仍按 70/20/10 切分。

## 3. 异常检测（Anomaly Detection）

异常检测的加载器要求**固定文件名**，只要把文件按名字放对位置即可（不需要改代码）。

### 3.1 PSM 风格（CSV，最易做）

需要三个文件，放在 `dataset/MyAnomaly/`：

```text
dataset/MyAnomaly/
├── Train.csv        # 训练集（正常数据）
├── Test.csv         # 测试集（含正常与异常）
└── Test_label.csv   # 测试集标签
```

格式：

- `Train.csv`：第一列时间戳（任意名），其余列是特征；**第二列起**才会被使用（代码 `values[:, 1:]`）；
- `Test.csv`：同样格式；
- `Test_label.csv`：第一列时间戳，第二列是标签（0=正常，1=异常）。

运行：

```bash
python run.py --task_name anomaly_detection --is_training 1 --model Bi_FI \
  --model_id MyAnomaly --data PSM \
  --root_path ../dataset/MyAnomaly/ \
  --seq_len 100 --enc_in <特征数> --dec_in <特征数> --c_out <特征数> \
  --d_model 512 --batch_size 128 --learning_rate 0.0001 \
  --train_epochs 10 --anomaly_ratio 1
```

### 3.2 MSL / SMAP / SMD 风格（numpy 数组）

需要三个 `.npy` 文件，放在 `dataset/MyAnomaly/`：

```text
dataset/MyAnomaly/
├── MyAnomaly_train.npy        # 训练数据（float 数组）
├── MyAnomaly_test.npy         # 测试数据
└── MyAnomaly_test_label.npy   # 测试标签（0/1）
```

文件名必须与数据集名一致：如果 `--data MSL`，就用 `MSL_train.npy`；`--data SMD` 就用 `SMD_train.npy`，以此类推。

用 Python 生成示例：

```python
import numpy as np
np.save("MyAnomaly_train.npy", train_array)          # shape (N_train, M)
np.save("MyAnomaly_test.npy", test_array)            # shape (N_test, M)
np.save("MyAnomaly_test_label.npy", label_array)     # shape (N_test,) 或 (N_test,1)
```

运行：`--data MSL`（或 SMAP / SMD），`--root_path ../dataset/MyAnomaly/`，`--enc_in <M>`。

### 3.3 SWAT 风格（两个 CSV）

```text
dataset/MyAnomaly/
├── swat_train2.csv   # 训练集：纯数值，前 M 列为特征（无时间列）
└── swat2.csv         # 测试集：前 M 列为特征，最后一列为 0/1 标签
```

运行：`--data SWAT`，`--enc_in <M>`（特征数，不含标签列）。

### 3.4 关键点

- 训练集只用**正常数据**；测试集混合正常与异常，标签用于评估；
- `--seq_len`（窗口长度，默认 100）决定每次输入多少步；
- `--anomaly_ratio`（默认 1，表示 1%）决定判定阈值：用训练集和测试集的重建误差分位数确定阈值，值越小阈值越严；
- 数据会被自动标准化（StandardScaler），你不需要手动归一化。

## 4. 分类（Classification / UEA）

### 4.1 文件要求

每个数据集一个文件夹，文件夹名就是数据集名，里面两个文件：

```text
dataset/MyClass/
├── MyClass_TRAIN.ts
└── MyClass_TEST.ts
```

文件名必须是 `<文件夹名>_TRAIN.ts` 和 `<文件夹名>_TEST.ts`。

### 4.2 `.ts` 文件格式（TSC 长格式）

文件结构：

```text
@problemName MyClass
@dimensions 3
@equalLength true
@classLabels 0 1 2
@data
...样本行...
```

- `@` 开头的是元信息，解析器会忽略（除 `@data` 作为数据起始标记）；
- `@data` 之后每行一个样本；
- 每行 = 多个通道，**通道之间用冒号 `:` 分隔**，**最后一个冒号后是标签**；
- 每个通道内的数值用逗号分隔；
- 标签可以是数字，也可以是字符串（如 `positivity`）；
- 缺失值用 `?` 表示。

示例（3 通道、每通道 4 个点、二分类）：

```text
@problemName MyClass
@dimensions 3
@equalLength true
@classLabels 0 1
@data
1.0,1.1,1.2,1.3:2.0,2.1,2.2,2.3:3.0,3.1,3.2,3.3:0
0.9,0.8,0.7,0.6:1.9,1.8,1.7,1.6:2.9,2.8,2.7,2.6:1
...
```

也兼容括号格式：`(1.0,1.1,1.2),(2.0,2.1,2.2):0`。

### 4.3 运行命令

```bash
python run.py --task_name classification --is_training 1 --model Bi_FI \
  --model_id MyClass --data UEA \
  --root_path ../dataset/MyClass/ \
  --e_layers 3 --batch_size 16 --d_model 128 --d_ff 256 \
  --learning_rate 0.001 --train_epochs 100 --patience 10
```

说明：

- `--model_id` 建议与数据集名一致；
- `--enc_in` 会被代码自动覆盖为“通道数”（`.ts` 里的通道数），不用手动填；
- 每个样本长度可以不同：代码会按最长样本 padding（不足补零），并用 padding mask 标记；
- 标签类别数由代码从文件自动统计，不用手动填。

### 4.4 如何从 CSV 转成 .ts（小工具示例）

如果你的数据是“每个样本一个 CSV”，可以写脚本转换。核心逻辑：

```python
def to_ts_line(sample, label):
    # sample: numpy 数组 shape (T, M)，M 个通道、每通道 T 个点
    channels = [",".join(f"{v:.6f}" for v in sample[:, m]) for m in range(sample.shape[1])]
    return ":".join(channels) + f":{label}"
```

把训练样本逐行写入 `MyClass_TRAIN.ts`（前面加上元信息头），测试样本写入 `MyClass_TEST.ts` 即可。

## 6. 验证数据能否被正确加载（自检）

跑完整训练之前，先用几行 Python 确认加载正常：

```python
import sys, types
sys.path.insert(0, "method_lib")
from data_provider.data_factory import data_provider

args = types.SimpleNamespace(
    data="custom", root_path="dataset/my_data/", data_path="temperature.csv",
    features="M", target="OT", embed="timeF", freq="h",
    seq_len=96, label_len=48, pred_len=96,
    task_name="long_term_forecast", batch_size=32,
    num_workers=0, enc_in=4, dec_in=4, c_out=4, anomaly_ratio=1,

```

如果形状、样本数符合预期，说明数据入口没问题，可以开始训练。

## 7. 常见问题（FAQ）

**Q1：报错 `KeyError: 'OT'`？**
CSV 里没有 `OT` 列。把最后一列改名为 `OT`，或在命令里加 `--target <该列名>`。

**Q2：报错 `KeyError: 't'` 或 `Invalid frequency`？**
`--freq t` 在 pandas 3 下需要映射，本库已修复；如果你用的是分钟级数据，用 `--freq t`；小时用 `h`，天用 `d`。

**Q3：数据量很大，加载慢怎么办？**
把 CSV 转成更紧凑的格式，或只保留需要的列；`--num_workers 4`（或 8）可加速数据读取。

**Q4：变量数很多（比如 300+）报显存不足？**
用 `d_model=512`（或更大）时注意显存；ECL 这类大变量数据集可把 `--batch_size` 降到 16。

**Q5：分类样本长度不一致会怎样？**
代码按最长样本 padding，并生成 padding mask；模型会忽略填充位置，不影响训练。

**Q6：异常检测标签必须是 0/1 吗？**
是的，阈值判定按二分类进行；多类异常请先合并成 0/1。

**Q7：我想用自己的文件命名，不想叫 Train.csv？**
可以修改 `data_provider/data_loader.py` 中对应加载器的文件名，但更推荐遵循现有约定（不改代码，方便后续同步）。
